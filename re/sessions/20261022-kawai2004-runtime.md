The direct `WINXPSP3` launch was deliberately not used for these probes because
it calls `SetDisplayMode(800, 600, 16)` and changes the host desktop. The DxWnd
windowed path leaves the desktop at 2560 × 1440.

## Method

1. Start the release package in windowed mode and wait for the title form.
2. Find the form client origin with `ClientToScreen`; the client is 800 × 600.
3. Read the game's VB array descriptor at `0x0041F0F0` and follow the data
   pointer at `0x0041F118`.
4. Interpret the array as 18 columns × 11 rows of 6-byte cells:
   - `u16 present` (`0xFFFF` = tile present, `0` = empty),
   - `u16 visual_id` (sprite index),
   - `u16 match_id` (normal tiles equal `visual_id`; special tiles use a group).
5. Calibrate the level-1/2 screen grid from white tile borders:
   - tile columns start at client `x = 53`, step `40`;
   - tile rows start at client `y = 106`, step `50`;
   - cell centre `x = 73 + (col - 1) * 40`,
     `y = 131 + (row - 1) * 50`.
6. Click a candidate pair and re-read the board, score, remaining count, and
   timer. During automated clearing, the timer field was instrumented
   (`0x0041F1B4` set to 200000 ms) to prevent incidental expiry. Time-decay
   and cap conclusions use the unaveraged observations, not the patch.

## Observed state addresses

| Address | Width | Observed meaning |
| --- | ---: | --- |
| `0x0041F0F0` | array descriptor | VB SAFEARRAY descriptor for the board |
| `0x0041F0F4` / `0x0041F104` | u32 | 6 / 18 (element bytes / columns) |
| `0x0041F118` | pointer | board data pointer (heap) |
| `0x0041F11C` / `0x0041F124` | u32 | 11 / 18 (rows / columns) |
| `0x0041F13C` | u16 | remaining tiles |
| `0x0041F140` | u32 | score |
| `0x0041F1B4` | u32 | timer, milliseconds (decreases at 1000/s) |
| `0x0041F1B2` | u16 | incrementing frame/update counter |
| `0x0041F148` … `0x0041F160` | u16 | resource/star/level-related counters; not fully decoded |
| `0x0041F166` | u16 | observed as 1 after the card bonus; not decoded |

The descriptor is not the static address of the data: `0x0041F118` holds a
heap pointer and changes when the round/array is recreated.

## Timeline and measurements

### Level 1, fresh round

- Board: 144 present tiles, 34 normal visual IDs ×4 each, 8 special visual IDs
  (34–41) ×1 each.
- Score: 0.
- Timer read approximately 1 second after start: 224016 ms. The timer decreases
  exactly 2000 ms per 2 seconds. The maximum is likely 225000 ms (3:45), but a
  direct first-frame read was not captured.
- First match: `(1,11)-(1,12)` (visual 1) accepted through the outer border?
  No, this pair was adjacent. Score 0→4, remaining 144→142. Timer increased
  only 547 ms because it was near its cap.
- Later match: score 4→8, remaining 142→140, timer +3672 ms after a 0.2 s
  observation window; a further match measured +3938 ms with 89 ms elapsed.
  This is consistent with a **+4000 ms** match bonus, minus elapsed time.
- Another match via a two-turn path that went through the outer border:
  `(1,7)-(1,10)`, score 16→20, remaining 136→134, timer +3938 ms (89 ms
  elapsed). The game accepted the border route.
- Automated clear of all 72 pairs on level 1:
  - score 284 after the penultimate pair;
  - final pair 284→548 (remaining 2→0);
  - next level start score 1448.
  - The exact split between a last-pair/clear bonus and a next-level bonus has
    not yet been isolated.

### Level 2

- Board: 144 tiles at start; score carried in at 1448.
- Level name: `第02關 石沉大海`.
- Chance panel icon: Rapidash, visual ID 13.
- A Spearow pair (visual 6) scored 1448→1456 (+8) and did not change stars.
- A Rapidash pair (visual 13) scored 1456→1464 (+8) and changed the HUD stars

- Three stars then opened a card screen with the text

- After the card screen, the board still contained 86 tiles; the remaining
  tiles were on the same 16 × 9 grid with holes, not a new board shape. This is
  consistent with the free card-close shuffle decoded in RE-0012/RE-0018, which

## Controlled score, difficulty, and clear probes

These probes used read/write instrumentation on a scratch game process. They
changed only preconditions (difficulty selection, timer value, or the set of
remaining board cells) and then let the original code run.

### Difficulty

| Menu | `0x41f180` | Level-1 max timer | Resources | First pair score |
| --- | --- | --- | --- | --- |
| 弱 | 0 | 320000 ms | 8/8 | +1 |
| 強 | 1 | 225000 ms | 5/5 | +4 |
| 超強 | 2 | 160000 ms | 5/5 | +9 |

The first match at each difficulty was capped by the initial maximum timer, so
the observed post-click delta was smaller than the nominal match bonus.

### Clear bonus

With the board reduced to one adjacent matching pair and the remaining counter
set to 2:

| Level / difficulty | Timer before final pair | Final score | Decomposition |
| --- | --- | --- | --- |
| L1 / 1 | 1000 ms | 120 | 4 pair + 100 base + 4*4 time |
| L1 / 1 | 10000 ms | 156 | 4 pair + 100 base + 4*13 time |
| L2 / 1 | 200000 ms | 1988 | +8 pair + 200 base + 8*203 time |

The level-2 clear score counts up during the animation; an immediate read was
1156, and the final overlay showed 1988.

Continuing a level-1 clear gave level 2 with score 156, max timer 210000,
resources 6/6. Continuing a level-2 clear gave level 3 with score 1988, max
timer 195000, resources 7/7. The continuation itself adds no score.

## Resource, hint, shuffle, and high-score probes

- The left top-right icon is the **shuffle** (internal B, `0x41F1AE`); clicking
  it changed the board hash and decremented B from 5 to 4.
- The right top-right icon is the **hint** (internal A, `0x41F1AC`); clicking
  it left the board hash unchanged and decremented A from 5 to 4. It sets
  `0x41F158 = -1` until the next match.
- A controlled card pick confirmed the reward code and resource effects; the
  card deck was a shuffled permutation of 0..17.
- A no-move probe with only two non-matching tiles did not decrement B, so
  auto-shuffle on no moves is still read only from the match handler.
- The high-score file was found at
  `C:\Users\<user>\AppData\Local\VirtualStore\Windows\kawai2004.hst`.
  It is 660 bytes. The observed nonzero records were 24 and 4 at 22-byte
  entry indices 10 and 11; the live screen also showed a default 100.
- A controlled score of 7777 was forced through the time-out lose overlay.
  The high-score name screen appeared, and after Enter the new record was
  written at entry index **10**, with the old 24/4 shifting to 11/12. This
  confirms three contiguous 10-entry tables and that difficulty 1 uses the
  second table. The original high-score file was restored afterward.
- The live form object at `0x733e70` had vtable `0x41feb8`. Its slots point to
  relative-jump thunks; decoding them gives the exact method map in RE-0015.
  The move finder is `0x40b400`, the path checker `0x40b610`, and the card deck
  initializer `0x40d230`.
- The hint probe set the flag and consumed one A. On a normal fresh board the
  fields `0x41F15A`–`0x41F160` were `(2,1)` and `(12,1)` interpreted as
  **(column,row)**, and the screenshot showed magenta borders on row 1,
  columns 2 and 12. After matching that pair they advanced to `(4,1)` and
  `(6,1)`. The hint uses the most recent move-finder pair and does not
  recompute on click.
- Setting score 7777 and timer 0 produced state 1 and the `挑戰失敗` overlay
  with both `時間已用完` and `無牌可消除` text. Clicking opened the name-entry
  screen; Enter saved the record to table 1 and returned to the menu.
- The path dispatcher `0x40b610` was read: same-row checks go to `0x40b6e0`,
  same-column to `0x40baa0`, and mixed row/column to `0x40be60`/`0x40c830`.
- The in-game `遊戲說明` screen confirms `不得超過二個轉折`, `不能穿過其他牌`,
  and `左鍵-選取，右鍵-取消`.
- Correction: the original README says each of the 11 levels has a different
  `消牌重整方式`. The level-specific vtable methods are board rearrangements,
  not visual effects. Static decompilation confirms L2 compacts columns down;
  L3 compacts rows left. L4–L11 remain open.
- Correctness policy: this repository now records that correctness outranks
  speed, convenience, and preserving earlier conclusions; guesses must not be
  promoted to `confirmed`.
- Controlled level-1 starts at difficulty 0 and 2 both had 144 tiles and the
  same 34×4 + eight-special multiset as difficulty 1.
- Pause at client `(630,13)` froze the timer (`195860` unchanged over two
  seconds) and showed `GAME PAUSE`; clicking the overlay resumed decay. This
  probe did not read B or the board. A later live probe plus the v1.01 README
  show that pause entry only freezes the timer; the resume click spends one B
  and reshuffles (RE-0017, 2026-10-23 pause-reshuffle session).
- Exit at client `(752,13)` returned to the menu without a prompt or save.
- `最佳記錄` at menu client `(565,252)` showed only persisted rows 24 and 4;
  the earlier visible 100 was the pending current-run score on the name-entry
  screen, not a default file row.

## Frida check of the level-start call graph

Frida 17.24.3 was attached to the windowed process and the candidate routines
`0x4087b0`–`0x40afa0` were hooked. A single level-1 start produced exactly
three entries, all from the same caller `0x40dad0`:

```text
0x40dd7d -> 0x4087b0
0x40dd84 -> 0x408c00
0x40dd8b -> 0x408b20
```

The instruction view of `0x40dad0` shows the corresponding vtable calls:

```text
0x40dd77  CALL [EDI+0x70c]
0x40dd7e  CALL [EDI+0x714]
0x40dd85  CALL [EDI+0x710]
```

It also contains the timer and resource initialization:

```text
MOV EAX, [0x41f184]
IMUL EAX, EAX, 0x3e8
MOV [0x41f184], EAX
MOV [0x41f1b4], EAX
...
CMP word [0x41f166], 0   ; level index 0 = first level
...
MOVSX EAX, word [0x41f180]
...
; value 0 -> 8, value 1 or 2 -> 5
MOV [0x41f1ac], AX
MOV [0x41f1ae], AX
```

A live level-1 state read `0x41f180 = 1`, `0x41f184 = 225000`,
`0x41f1ac = 5`, and `0x41f1ae = 5`.

This rejects the earlier "eleven consecutive functions = one per level"
hypothesis: at least three of them are common form methods called on every
level start.

## Limitations

- Automated runs used a timer patch; do not use them to infer natural time
  decay beyond the separately measured 1000 ms/s rate.
- The exact clear bonus, the star reset policy, the card reward distribution,
  the current-chance selection timing, and the 11 level-specific reshuffle
  routines are still open.
- The 38-tile level-2 state rejected a pair that a generic two-turn BFS
  considered legal. The cause may be a level-specific path/mask rule, a stale
  board read during a screen transition, or an input timing issue. Do not
  promote the generic BFS result as the original rule until isolated.
- Sprite names are descriptive only; the authoritative values are the visual
  IDs in the memory dump.
