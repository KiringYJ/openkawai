# openkawai

A web reimplementation of **KAWAI 連連看 2004** — built as a clean-room,
source-only project that studies the original game's observable behaviour and
rebuilds it for the browser.

> **Status: M0 bootstrap.** The board, two-turn pathfinding, timer, scoring,
> hints, and shuffle work. Board size, tile vocabulary, timing, and scoring are
> provisional until they are recorded with evidence in [`re/`](re/).

## Try it

Requires Node.js 22.12+ or 24+. The repository pins Node 24.16.0 in
`.node-version`.

```sh
npm install
npm run dev
```

Open <http://localhost:5173>. Production output is written to `dist/`:

```sh
npm run build
npm run preview
```

| Command             | What it does                                  |
| ------------------- | --------------------------------------------- |
| `npm run dev`       | Vite development server.                      |
| `npm run build`     | Type-check, then build static assets.         |
| `npm run preview`   | Serve the production build locally.           |
| `npm test`          | Run the Vitest suite once.                    |
| `npm run test:watch`| Re-run tests while editing.                   |
| `npm run typecheck` | Run TypeScript without emitting files.        |

## What works in M0

- A 12 × 8 board with 12 placeholder tile kinds and 48 pairs.
- Selection, deselection, and match resolution.
- Connections with zero, one, or two turns; the outer border is traversable.
- A five-minute countdown, combo scoring, hints, shuffles, pause, and restart.
- Automatic pause when the tab becomes hidden.
- Responsive layout and reduced-motion support.

These are implementation defaults, not claims about the original game. The
current rule set lives in [`src/content/layouts.ts`](src/content/layouts.ts),
[`src/core/board.ts`](src/core/board.ts), and
[`src/game/session.ts`](src/game/session.ts).

## Repository map

```text
src/
  core/       Pure board, pathfinding, and seeded RNG. No DOM.
  game/       Round state: selection, scoring, timer, pause, restart.
  ui/         DOM rendering, input, path overlay, dialogs.
  content/    Placeholder tile kinds and layout definitions.
tests/        Unit tests for the pure core and game session.
re/           Evidence-first reverse-engineering workspace.
docs/         Architecture, roadmap, and asset policy.
```

The game is deliberately framework-free. The DOM shell is small, the board is
a CSS grid, and the connection path is an SVG polyline. This keeps the core
portable to another renderer later and makes the reverse-engineered rules the
main source of complexity.

## Agent workspace

Agent policy is generated by
[`agent-workbench`](https://github.com/KiringYJ/agent-workbench) with the
`frontend` profile. `AI_AGENT_GUIDE.md` is managed; project-specific context
lives in `AI_AGENT_PROJECT.md`. The portable prompts and skills are synced under
`.agents/`, with a generated Claude discovery mirror under `.claude/skills/`.
Re-run the upstream sync prompt to update the generated files instead of editing
them by hand.

## Reverse engineering

`re/` is the project's evidence log, not a dump of decompiled code. Each finding
records what was observed, how, and how confident we are. See
[`re/README.md`](re/README.md) for the workflow and
[`re/scope.md`](re/scope.md) for the known target and the current unknowns.

The sibling project
[`kawai-win11-compat`](https://github.com/KiringYJ/kawai-win11-compat) documents
a source-only Windows 11 compatibility launcher for the 2003, 2004, and 2005
games. It is the preferred starting point for obtaining a lawfully owned local
copy and for runtime observations.
